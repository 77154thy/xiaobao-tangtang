# 🔥 小宝汤汤爱闯关 💧

双人实时联机横版闯关网页游戏 —— 类「欢乐冰火人」玩法。  
**小宝**（🔥火娃）与**汤汤**（💧水娃）组队闯关：火会烫到汤汤、水会淋湿小宝、毒液谁都怕！  
支持 iOS / Android 手机浏览器与桌面浏览器，横屏游玩，异地联机。

## ✨ 游戏特性

| 特性      | 说明                                                               |
| ------- | ---------------------------------------------------------------- |
| 两种模式    | **双侠同行**：两人各自控制角色配合闯关（经典冰火人）；**心有灵犀**：一人控方向、一人控跳跃，两个角色同步移动（考验默契） |
| 240 个关卡 | 每种模式 120 关，难度从基础跳跃到移动平台、压力板大门、弹簧、定时尖刺、碎裂平台层层递进，每关都需要动脑配合         |
| 无限复活    | 死亡后自动回到起点复活，无死亡次数限制                                              |
| 自由选关    | 全关卡自由选择，记录每关最佳用时（本地保存）                                           |
| 低延迟联机   | 输入转发架构：只传输按键状态（约 30 字节），本机操作零延迟，对面角色最迟 50ms 跟随                   |
| 断线重连    | 掉线 60 秒内重连自动回到房间继续玩                                              |
| 零素材     | Canvas 2D 手绘 + WebAudio 合成音效，无需下载任何图片/音频                         |

**通关祝贺语**：恭喜小宝和汤汤闯关成功，小宝真棒，加油下一关~（通关后 5 秒自动进入下一关，也可手动选关/重玩）

## 🚀 本地启动

环境要求：Node.js ≥ 16

```bash
cd 小宝汤汤爱闯关
npm install
npm start
```

启动后看到：

```
  小宝汤汤爱闯关 - 服务已启动
  本机游玩:   http://localhost:3000
```

浏览器打开 <http://localhost:3000> 即可。

> 开发模式（文件改动自动重启）：`npm run dev`
>
> 无头自测（校验 240 关的确定性/出生点/引擎模拟，开发用）：`node scripts/selftest.js`

## 👥 双人联机测试

### 方式一：同一台电脑（最快）

1. 打开两个浏览器窗口（建议一个普通窗口 + 一个无痕窗口，避免登录态混淆）；
2. 窗口 A：输入昵称 → **创建房间**，记下 4 位房间号；
3. 窗口 B：输入昵称 → 输入房间号 → **加入房间**；
4. 任意一方点「我准备好了」，房主点「🚀 开始闯关」即可联机游玩。

### 方式二：手机 + 电脑（同一 WiFi）

1. 电脑启动服务后，按 `Win + R` 输入 `cmd` 回车，执行 `ipconfig`，找到「无线局域网适配器 WLAN」下的 **IPv4 地址**（如 `192.168.1.8`）；
2. 手机连上**同一个 WiFi**，浏览器访问 `http://192.168.1.8:3000`（换成你的 IP）；
3. 一台手机创建房间，另一台（或电脑）加入房间。

> 若手机访问不了：检查 Windows 防火墙是否放行了 Node.js（首次启动时弹窗选择「允许」），或到防火墙设置里手动放行 3000 端口。

### 方式三：异地联机（不同 WiFi / 不同城市）

两种方式任选（保姆级步骤见 [部署指南.md](部署指南.md)）：

- **最快**：双击 `一键异地联机.bat` → 把窗口里出现的 `https://xxxx.lhr.life` 网址发给小伙伴即可
  （0 注册 0 下载，2 分钟搞定；需要你的电脑保持开机）；
- **固定网址**：部署到 Render（见下节），得到 `https://你的应用.onrender.com`，随时可玩。

## ☁️ 部署上线

> 📖 **完整图文步骤见 [部署指南.md](部署指南.md)**，四种方案从易到难：
> ① SSH 隧道（一键 bat，最快）→ ② Render 固定部署（推荐长期用，自带 `render.yaml` 蓝图，
> Region 建议选 Singapore）→ ③ cloudflared 隧道（备选）→ ④ 自有服务器 + Nginx。

本项目是**单服务**（Express 同时托管网页与 Socket.IO），部署最简单的方式：

### 方案 A：Render（推荐，有免费额度）

1. 把本项目推送到 GitHub 仓库；
2. 打开 [render.com](https://render.com) → New → **Web Service** → 连接仓库；
3. 配置：
   - Runtime: `Node`
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Region 建议选 **Singapore**（国内访问延迟更低）
4. 创建后得到 `https://你的应用.onrender.com`，两人访问即可联机。  
   （免费实例闲置会休眠，首次访问需等 30 秒左右唤醒）

Railway / Zeabur / 阿里云等任何支持 Node 的平台同理：  
**Build: `npm install`，Start: `npm start`，端口读取环境变量 `PORT`（已适配）。**

### 方案 B：前端 Vercel + 后端 Render（可选拆分）

1. 后端按方案 A 部署到 Render，得到如 `https://xxx.onrender.com`；
2. 前端 `public/` 目录单独部署到 Vercel/Netlify；
3. 修改 `public/js/net.js` 中 `io({...})` 为 `io('https://xxx.onrender.com', {...})`（跨域已在服务端放行）；
4. 把拆分后的后端地址也填入浏览器访问的 Vercel 域名说明里（或让玩家直接访问后端地址游玩，最简单）。

> ⚠️ 想要「不同地方也能玩」最省事的做法：**直接把方案 A 的单一网址发给朋友**，前后端同源，无需任何跨域配置。

### 方案 C：自己的服务器（VPS / 家里的电脑 + 内网穿透）

```bash
npm install
PORT=3000 npm start        # 或 set PORT=3000 && npm start（Windows）
```

- 有公网 IP / 已备案域名：用 Nginx 反向代理 3000 端口（记得支持 WebSocket 升级头）；
- 无公网：用 cpolar / 花生壳 / frp 等内网穿透工具把 3000 端口映射到公网。

## 🔌 Socket.IO 事件一览

**客户端 → 服务端**：`createRoom` `joinRoom` `playerReady` `changeMode` `swapDuty` `selectLevel` `startGame` `playerInput` `levelComplete` `playerDied` `stateSnapshot` `leaveRoom` `pingx`

**服务端 → 客户端**：`roomCreated` `roomJoined` `playerListUpdate` `gameStart` `levelStart` `gameStateUpdate` `gameOver` `opponentInput` `playerDied` `opponentLeft` `opponentRejoined` `error`

## 🧠 同步架构说明（低延迟的关键）

- **输入转发**：客户端只把按键状态（`{seq,l,r,j}`，约 30 字节）发给服务器，服务器**原样转发**给对手，不做任何游戏逻辑——服务器近乎无状态，转发耗时 <1ms；
- **本地模拟**：双端各自跑同一套 60Hz 确定性物理，自己的角色零输入延迟；
- **软校正**：房主每 500ms 广播一次位置快照，客人据此 gently 校正对手位置与关卡时钟，消除累积漂移；
- **通关仲裁**：任一端检测到双角色到达出口即上报，服务器校验关卡号（先到先得、幂等）后广播结算，结算用时以服务器时间为准。

## 📦 数据存储

当前房间状态保存在**内存**（重启即清空，符合闯关游戏的临时性）。`roomManager.js` 已抽象出接口，后续可平滑替换为 Redis（多实例部署）或 SQLite（持久化战绩）。

## ❓ 常见问题

**Q：手机竖屏打开提示旋转？**  
A：本游戏为横屏设计，请旋转手机；进入关卡后会自动尝试锁定横屏。

**Q：没有声音？**  
A：iOS/Android 浏览器要求用户先触摸屏幕才会播放声音，点击一下屏幕任意位置即可。

**Q：两人玩的进度一样吗？对手卡住怎么办？**  
A：关卡由相同种子生成，双端画面完全一致；对手掉线会提示等待 60 秒，超时房间关闭。

**Q：想改物理手感/加关卡？**  
A：物理参数在 `public/js/game/constants.js`，关卡片段模板在 `public/js/game/levelGen.js`（双端文件必须一致！），服务端关卡总数在 `server/gameHandler.js` 的 `LEVELS_PER_MODE`。
